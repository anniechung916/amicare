## P1 — Security (pre-launch)

### WebSocket Authentication
**What:** Add JWT token validation to the /ws WebSocket connection.
**Why:** Currently anyone who knows the URL can connect and receive live patient names, insurance companies, and call transcripts in real time. Patient PII is being broadcast unauthenticated.
**How to apply:** Pass JWT as a query param on connect (`/ws?token=...`), validate on the server in `websocket.py` before calling `manager.connect()`. This is being fixed in the current build.
**Effort:** S | **Priority:** P1 | **Blocked by:** JWT auth must be built first.

### Remove or Protect /api/test-call
**What:** Delete the unauthenticated `/api/test-call` endpoint or add auth + rate limiting.
**Why:** Anyone on the internet can trigger a real Twilio phone call to any number, running up your bill. It also creates "TEST CALL" tickets in the database.
**How to apply:** Either delete the endpoint entirely (recommended) or add JWT auth + restrict to admin role.
**Effort:** S | **Priority:** P1 | **Depends on:** JWT auth.

## P2 — Core Product (post-demo)

### Clearinghouse Integration (Real Claim Submission)
**What:** Integrate with Change Healthcare or Availity to submit CMS-1500 claims electronically on the patient's behalf.
**Why:** Right now the patient has to manually upload their form to their insurer's portal. Real value (and the 20% fee model) requires AmiCare to submit automatically.
**How to apply:** EDI 837P format submission via a clearinghouse. Requires enrollment as a billing service, NPI of the submitting entity, and HIPAA BAA with the clearinghouse.
**Effort:** XL | **Priority:** P2 | **Depends on:** Working demo + funding.

## P3 — Quality of Life (later)

### Multi-tenant / Organization Support
**What:** Support multiple practices under one account, with role-based access (admin, billing staff).
**Why:** A single practice can use the current single-user model, but selling to multiple offices requires org isolation.
**Effort:** L | **Priority:** P3

### EHR Integration
**What:** Auto-import patient insurance data from Epic, Athena, or other EHR systems.
**Why:** Eliminates manual intake data entry for offices already using an EHR.
**Effort:** XL | **Priority:** P3

### Automated Claim Status Polling
**What:** After claim submission, periodically check with the insurer for reimbursement status and update the ticket.
**Why:** Closes the loop on the 20% fee collection — AmiCare needs to know when the insurer paid.
**Effort:** M | **Priority:** P3 | **Depends on:** Clearinghouse integration.
